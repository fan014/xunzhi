# 00 · 循知项目快速上手（新对话必读）

> 快照：2026-11-24。代码是唯一事实来源；本文用于新对话快速恢复项目上下文，行号会变化，定位以文件 + 函数名为准。

## 1. 这个项目是什么

「循知」是面向学生的中文学习助手：上传教材/课件/笔记/截图，用一句话说明学习进度，生成可阅读的讲义和可直接作答的复习题；讲义与题目都能回到原资料，答错后可按考点再练。个人单机使用，唯一模型配置是服务端 `.env` 中的 `DEEPSEEK_API_KEY`。

当前主流程：

```text
上传资料 / 选知识库
  → 诊断问答（确定范围与薄弱点）
  → 学习计划预览与确认（模块 + 考点 + 题量 + 时间安排）
  → 确认后保存日程任务并正式生成学习计划
  → 学习日历（今日任务 / 进度 / 任务进入）
  → 学习页阅读（左图右文、翻页、续学）
  → 分模块练习 / 综合复习
  → 交卷与掌握评估
  → 个人档案驱动下一轮
```

## 2. 技术栈与边界

- 后端：Python 3.12 + FastAPI + SQLAlchemy + SQLite；不引入新的后端框架。
- 前端：原生 JavaScript（`app/static/*.js`）+ 原生 CSS；不引入 React/Vue。
- 可视化：现有二维 SVG + CSS（`visual.js`），不引入新样式库。
- 桌面：pywebview + WebView2，窗口标题「循知」，桌面快捷方式「循知.lnk」。
- 模型：DeepSeek；测试环境强制模型替身，测试不读取 `.env`、不调用真实 API。
- 数据：本地 `data/xunzhi.sqlite3` + `data/sources` / `data/derived` / `data/logs`；目录由 `XUNZHI_DATA_DIR` 覆盖。

## 5. 上一轮（2026-11-24）：学习页图示与原图对应

### 5.1 数据契约

- `ModelModule` 新增有序 `pages` 与 `recap`。
- 每条 `LearningPage`：`page_id`、`knowledge_point_ids`、`title`、`explanation`、`visual`、`related_sources`。
- `PageVisual.type` 四种：`text` / `source_asset` / `comparison` / `step_sequence`。
- 持久化不改表：页面存为 `handout_section.section_type=module_page`，回顾存为 `module_recap`，结构放 `content_json`。
- 页面引用与资料原图引用都写现有 `citation`，`owner_id` 指向页面 section；`visual.citation_id` 回填。
- `GET /api/packs/{id}` 返回 `modules[].pages` 与 `modules[].recap`；讲义 `handout` 已排除页面/回顾，避免重复。

### 5.2 服务端行为

- 计划模块路径要求 `pages` 非空：缺失返回 `module_pages_missing`，批次与单次路径都带修正提示重试；仍失败则不发布缺页成品。
- `sanitize_module_pages` 对图示做降级：
  - `source_asset` 必须引用本次实际发送、高置信、类型为 `page_image/image_region` 的证据；
  - `comparison` 至少两张卡；
  - `step_sequence` 校验节点/连线/步骤引用与答案 ID；
  - 失败只降级为文字页并写 `visual.notice`，不阻断翻页。
- 取证时对 `image_region` 按框裁剪后发送；`P#` 与 `I#` 编号独立；两条件多页时优先发送区域图。
- 合并批次时 `visual.source_ref` 与 `related_sources[].ref` 一起重编号，页顺序随已确认模块顺序。
- 契约变更后：`PROMPT_VERSION="prompt_v3"`、`BATCH_CACHE_VERSION=4`；改输出结构要同步升级并防旧缓存误命中。

### 5.3 前端行为

- `reader.js` 优先按 `module.pages` 渲染；无 `pages` 的旧包由讲义段落派生文字页。
- 旧派生页可显示与该段有明确引用关系的资料图；新包文字页不自动把引用页图当主图。
- 末页优先读 `module.recap`，显示「条件 → 结果 → 常见误区」；最后模块显示 `cross_module`。
- `pack.js` 保存位置时提交 `module_id + page_id + view`；旧 `page_id` 找不到时回落到模块第一页。
- 已移除 `hasSwitch/hasTcp/hasLens` 关键词入口；`Maclaurin 展开`、`针孔成像` 不再被误挂交换机/凸透镜演示。
- 预置样例只能通过明确 `preset_id`（`switch_forward` / `tcp_handshake` / `lens_imaging`）选中。

- 服务端使用本机本地日期；`scheduled_date` 保存 `YYYY-MM-DD`，`completed_at` 保存本地时间，两者分开判断。

- 阅读/回顾只允许手动「标记学完」；练习任务只在实际交卷后完成（交卷事务内写入 `completion_source=practice`）。
- 2026-11-24 第二阶段第一项修复：日历练习链接携带 `task_id`，任务按正式题目稳定顺序绑定具体题目；分组草稿、分组交卷、分组结算，A 组交卷不完成 B 组，整卷交卷只完成被实际答案完整覆盖的组。

## 7. 必须遵守的工程约束

- 字段用 `snake_case` 语义命名（`page_id`、`knowledge_point_ids`、`related_sources`、`source_asset`、`option_id`）；代码标识符与枚举值用英文，界面文案用中文。
- 关联用稳定 ID；显示名可改，改名不能让历史记录失联。不要用名称或关键词批量推断关联。
- 改动尽量最小：保留现有列、状态机、元素 ID 与变量名；需要改绑定就同步更新。
- 正式练习继续关联原考点与模块；不要因新增页面结构改变判分与题量分配。
- 引用必须来自本次实际发送的证据；被预算裁掉、删除或范围外的证据不可引用，也不可绑定为资料原图。
- 新增数据库列/迁移时按 `app/infra/migrations.py` 现有方式兼容旧库；优先复用 JSON 列，不轻易新增表。
- 测试不读真实 Key、不调真实 API；真实 DeepSeek、浏览器与桌面点击由用户本机执行，结论按「通过／未执行／待验证」如实填报。
- 测试共享同一 SQLite 数据库时注意隔离；依赖「最近学习记录」的测试要在开头重置 `learning.positions` / `learning.last`。
- 改 `app/static` 或 `app/templates` 后升级模板中的 `?v=` 缓存串，否则 WebView2 会继续用旧脚本。
